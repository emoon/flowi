# flowi physical layout: split `include`/`src`, generated-is-the-public-surface, two-prefix includes

## Status

accepted (realizes the module structure decided in ADR-0031; depends on the IDL/generation model of
ADR-0030 and the direct-API/host-ownership split of ADR-0032). The tree layout and include rule below
are the current state. Partly superseded in detail: the build is one `flowi_objects` object library
plus the `flowi` shared library (not five library targets plus `flowi_static`), the quarantined
`flowi/src/host/` was deleted by ADR-0034, and the bucket-3 transient is resolved (the vfs types are
generated into `flowi/include/flowi/vfs/`; `ui_types.h` remains an internal header).

## Context

ADR-0031 decided *what* the modules are — a five-module DAG (`core`, `platform`, `vfs`, `render`,
`ui`) with provenance-revealing includes (`#include <flowi/core/arena.h>`) — and the `Fl`/`fl_`
symbol rename has already landed. What ADR-0031 did **not** pin is the *physical* tree: where files
sit on disk, what `<flowi/...>` resolves against, where api_gen writes, and how the absorbed foundation and the Rust crates are laid out. The tree at the time still
reflected the pre-release extraction: a vendored foundation tree, a flat `ui/generated/`, `renderer/`,
and the pre-release Rust crates. Includes resolved through a pile of overlapping
`target_include_directories` roots, so the same header was reachable under several spellings
depending on the caller.

Three facts discovered while scoping this work shape the decision:

- **The public C API is target ~100% generated.** Hand-writing public headers means hand-writing
  the Rust wrapping too, which does not scale. So the public surface *is* api_gen's output; every
  hand-written header is implementation detail. (Rust aims for majority-generated; tricky-ownership
  cases keep a manual façade.)
- **The host-prefixed plugin headers are not flowi's.** The vendored tree carried the *plugin-facing*
  API of the host — a separate surface from the internal foundation implementation headers. Per
  ADR-0032 the plugin boundary belongs to the host, so the entire host plugin-header directory
  leaves flowi.
- **Generated and hand-written headers collide by basename today** (8 in `ui/`: `image.h`,
  `layout.h`, `painter.h`, `signal.h`, `ui_list.h`, `ui_menu.h`, `ui_scroll.h`, `ui_selection.h`).
  They are complementary (the hand-written one `#include`s or sits beside its generated twin), not
  duplicates — an artifact of the in-flight IDL migration, where a type's hand-written
  form and its generated form coexist until the migration deletes the hand-written one.

## Decision

**flowi is one tree split by audience: `flowi/include/flowi/<module>/` is the generated public API,
`flowi/src/<module>/` is the implementation. The include *prefix* encodes audience.**

- **Root-level `flowi/`.** A real top-level `flowi/` directory; the on-disk path is the include
  path. No build-time staging/symlink indirection. `app/`, `tests/`, `examples/`, `external/`,
  `vendor/` remain root-level siblings.

- **Split public/impl tree.**
  - `flowi/include/flowi/<module>/*.h` — the **public C API, generated only**. api_gen emits here
    directly. Because the public tree is generated by construction, there is **no `generated/`
    subdirectory** — the directory *is* the generated surface.
  - `flowi/src/<module>/*.{c,h}` — implementation: `.c` plus all hand-written headers (internal
    cross-module types, private headers).

- **Two-prefix include rule, audience-encoded.**
  - `#include <flowi/<module>/x.h>` — a public, generated header. The `flowi/` prefix is **reserved**
    for generated public output.
  - `#include <<module>/x.h>` (e.g. `<core/arena.h>`, `<ui/ui_types.h>`) — a hand-written
    internal header used across modules.
  - `#include "x.h"` — a same-module / private header.

  This sidesteps the basename collision structurally: generated `<flowi/ui/layout.h>` and internal
  `<ui/layout.h>` are distinct spellings in distinct trees, so both can exist throughout the IDL
  migration. It also makes audience legible at every call site: the prefix tells you public-vs-internal
  before you open the file.

- **`base` is renamed to `core`.** The directory, the CMake target, and the `base`/`base_` filename
  stems all become `core`/unprefixed (`base.h`→`core.h`, `base_string.h`→`core/string.h`,
  `base_math.h`→`core/math.h`, …) — the module name already carries the provenance the `base_` stem
  used to.

- **Full DAG alignment in the build.** Five library targets `core`, `platform`, `vfs`, `render`,
  `ui` mirror the ADR-0031 table. `vfs` is split out of the old `base` lib; `backend`→`platform`;
  `render` keeps its software/GPU sub-split (the GPU lib stays EGL-gated). The aggregate
  static library target is renamed `flowi_static`.

- **The host plugin headers leave flowi**, in three fates:
  1. **Core-facade duplicates** (`arena`, `string`, `memory`, `path`, `log`, `jobs`, `types`,
     `perf_scope_api`, `file_watcher_api`, `settings_api`, `json_api`): flowi's few stray includes
     switch to the internal `<core/...>` header; the facade is deleted.
  2. **Pure host** (the host's metadata, media, playlist, cache, plugin-manifest and user headers):
     deleted from flowi (they live in the embedding host).
  3. **flowi-needed, no IDL home yet** (`ui_types`, `ui_theme`, `content_view`, `list`, `vfs_api`,
     `vfs_types`): re-homed as **internal** headers under the owning module
     (`flowi/src/ui/ui_types.h` → `<ui/ui_types.h>`, etc.), pending dissolution into `.def` by the
     IDL migration. This is an accepted transient — hand-written headers that
     "should" be generated — in the same spirit as ADR-0031's transient mixed-prefix window.

- **api_gen partitions C output by module; Rust relocates flat.** Each `.def` gains a `module`
  attribute (default `ui`; `arena` and `math_data` are `core`); the C emitter writes to
  `flowi/include/flowi/<module>/` and cross-includes as `<flowi/<module>/x.h>`. The Rust crates are
  renamed and their generated dirs relocated (`rust/flowi_sys/src/generated/`,
  `rust/flowi/src/generated/`) but stay flat; the `flowi::core`/`flowi::ui` Rust module paths are a
  separable follow-up, not part of this pass. A `.def`'s module assignment *is* its public include
  path, so reassigning a type's module later is a consumer-visible break — assignments are made
  deliberately and the `core` set is kept minimal.

- **Rust crate names use underscores throughout**: `flowi`, `flowi_sys`, `flowi_macros`, and later
  `flowi_core`, `flowi_core_sys`, `flowi_vfs`, `flowi_vfs_sys` (package == lib == the string in
  generated code, so there is no `-`/`_` translation to track). The crates live under `rust/`.

- **The host plugin/service subsystem is quarantined, not yet evicted.** *(Evicted since, by
  ADR-0034.)* `service_api`,
  `plugin_manager`, and `vfs_plugin_registry` are host-domain per ADR-0032 but are currently the
  wiring backbone (`vfs_init`/`plugin_manager_update` take a `service_api`; `vfs` pulls its driver
  from `plugin_manager`). They move into a labeled `flowi/src/host/` quarantine target (out of
  `core`), the pure-dead host headers are deleted, and `service_api.c` is stripped to what flowi
  actually compiles. **Full eviction is Phase 2 = ADR-0032 step 3/4** (re-cut the `vfs_init` seam,
  remove the registry, move the subsystem to the embedding host) — substantial, cross-repo, explicitly
  out of scope here.

### Sequencing

The move was staged as: Rust crate rename, api_gen C output relocation, then `core`, `vfs`, `platform`,
`render`, `ui`, the host quarantine, and the leaf/harness fixups, each green before the next. All of
it, and the cross-repo eviction of the quarantined host subsystem (ADR-0034), is done.

## Considered Options

- **Virtual `<flowi/...>` prefix via a build-time staging include dir.** Rejected: reintroduces the
  on-disk-path-lies-about-the-include-path indirection the rebrand exists to kill.

- **Co-located tree (`flowi/<module>/*.{c,h}` with generated in `flowi/<module>/generated/`), one
  repo-root include path ("Model A").** Considered as a lower-churn first step. Rejected as the
  *target* because it bakes in a guaranteed second mass-move of every public header once the IDL
  migration lets the public `include/` tree exist — ADR-0031 explicitly forbids throwaway renames.
  Model B reaches the end-state in one pass; the "public = generated" rule makes its public/private
  classification trivial (the only objection to Model B), so the staging argument for Model A falls
  away.

- **Flatten generated headers into the module dir now (no `generated/`, co-located).** Rejected:
  collides with the 8 hand-written twins. Flattening is only collision-free once the IDL migration
  deletes the twins — which the split tree achieves immediately via the two-prefix rule instead of
  waiting.

- **Hyphenated Rust crate names (`flowi-sys`).** More idiomatic for crates.io, but this is an
  in-repo lib; underscores keep package == lib == generated-code spelling identical and drop a class
  of `-`/`_` confusion. Revisit only if publishing.

- **Evict the host service subsystem now (single phase).** Rejected for this effort: it drags in the
  cross-repo ADR-0032 step-3 plugin-adapter work and the `vfs`↔`plugin_manager` untangle, turning a
  layout change into a host-architecture change. Quarantine keeps Phase 1 bounded and green and makes
  the eventual eviction an isolated deletion.

## Consequences

- ADR-0031's module DAG becomes physical: five source modules (one build target, see Status),
  `<flowi/<module>/…>` for public generated headers, `<<module>/…>` for internal cross-module headers.
- The public API surface is now literally a directory you could install: `flowi/include/flowi/`,
  generated, no hand-written headers, no `generated/` subdir.
- The host plugin headers leave flowi entirely; the host plugin SDK and service registry were
  quarantined in `flowi/src/host/` and then evicted (ADR-0034).
- A transient remains: bucket-3 hand-written headers (`ui_types`, `content_view`, `list`, `vfs_api`,
  …) live as internal `<module/…>` headers until the IDL migration authors them into
  `.def`, at which point they move to `flowi/include/flowi/<module>/` as generated output and the
  internal header is deleted — collisions already dissolved by then.
- `cargo regen` must stay byte-identical on re-run (`cargo regen-check` is the gate); the output
  paths and `scripts/format.sh`'s exclusions point at the generated locations (`flowi/include/flowi/**`,
  `rust/flowi*/.../generated`).
