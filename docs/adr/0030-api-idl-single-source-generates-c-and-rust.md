# The API IDL is the single source of truth; api_gen generates both C and Rust

## Status

accepted — partly superseded. The single-source IDL principle stands and is how the repository works
today: `api/*.def` generates the public C headers (`flowi/include/flowi/<module>/`), the Rust
`-sys` bindings, the safe Rust façade and the export list, all regenerated by `cargo regen`
(`codegen/`) and checked by `cargo regen-check`. What changed afterwards: the composed
`FlUiAPI`/`g_fl_ui` vtable as the *only* call path (and with it the hot-reload invariant and the
second output profile) was withdrawn by ADR-0032, and the public symbols are plain exported `fl_*`
functions (ADR-0058). `#[mirror]` and `#[seam]` are gone from the defs. The generator is a separate
public repository (ADR-0073). The text below keeps the original reasoning; read the vtable parts
with that in mind.

The standalone prefix is `Fl`/`fl_` (ADR-0031). This text uses that spelling throughout.

Today the binding architecture runs **C → def**: the hand-written C is the source of truth, the
`.def` IDL is a parasitic second description of it (`#[mirror(FlColor, "…")]`), and api_gen's C
output is only a `_Static_assert` drift tripwire. This duplicates every crossing fact several
times over. A single struct that crosses the boundary is spelled three times — the internal
render type (`FlColor`, `ui/render_ir.h`), the public plugin-ABI type
(a hand-laid-out header that punned onto the internal one), and the `#[mirror]` def. A
single API *function* is spelled **six** times: the plugin-vtable slot (`ui_api.h`), the
`ui_*_impl` prototype (`ui/ui.h`), the impl body (`ui/ui.c`), the `.fn = ui_*_impl` vtable
wiring (`ui/ui.c`), the `ui_*` convenience macro that injects the designated-initializer
config, and the Rust seam binding. Editing one fact means editing it in N places and trusting a
guard to catch a miss.

The mixed prefixes were a second symptom of the same root cause: the pre-release code carried the
prefixes of the host application it was extracted from. As a standalone toolkit, the prefix should be a
generator policy, not text baked by hand into hundreds of call sites.

## Decision

**The `.def` API IDL becomes the single source of truth. api_gen generates the entire crossing
surface — the C ABI headers *and* the Rust bindings — from it. The only hand-written C left is
function bodies.**

Concretely:

- **Defs are 100% prefix-free.** A type is `Color`, a function is `button`, an API is `Ui`. One
  generator constant pair drives all naming: `Fl` for C types, `fl_` for C functions.
- **Types are fully generated.** `ui_types.h` becomes an `@generated` header at its real include
  path. No hand-written C type for anything that crosses the boundary. Internal-only types
  (`FlCmd*`, render-IR commands) stay hand-written; opaque state (`TextInputState`) is declared
  *opaque* in the def (forward-decl only). The pun twins (an internal type and a
  hand-laid-out public copy) collapse into a single generated type.
- **Functions are generated down to the body.** For each function api_gen emits the API vtable
  slot, the `fl_<api>_<fn>` prototype, the vtable wiring, and the convenience macro (the
  designated-initializer config ergonomics). The human writes only the **body**, against the
  generated prototype — a signature drift fails to compile. (Today: no vtable slot or wiring is
  emitted; the generator emits the exported `fl_*` prototype, and the brace convenience macro only for
  functions whose trailing parameter is a `*Config` struct, e.g. `fl_button(...)` over
  `fl_button_impl(label, (FlWidgetConfig){...})`.)
- **The "API" is the core construct** (the foundation's existing Service-API vocabulary: the UI and log vtables, …). One def domain = one `Fl<Domain>API` fn-pointer struct, composed into a root
  `FlUiAPI`. The vtable is the *only* call path — convenience macros call through `g_fl_ui->…` —
  which makes it simultaneously the plugin ABI and the hot-reload boundary (callers go through the
  indirection, so the implementation behind it can be swapped). *(Withdrawn by ADR-0032.)*
  `#[mirror]` and `#[seam]` are retired.
- **Naming is a per-output profile.** The `Fl`/`fl_` standalone profile is built now. A second
  plugin profile — same defs, different prefix, plus the export glue — is *designed for but not
  built* until a host application actually loads flowi as a plugin. (Not built since: see ADR-0032.)
- **The Rust ergonomic layer shrinks.** api_gen generates `flowi_sys` raw bindings *plus*
  mechanical ergonomics driven by def annotations (`Default` derives, `AsRef<str>` conversions,
  opaque-handle newtypes). The `flowi` crate keeps only genuinely bespoke sugar (builders, the
  `extern "C"` panic trampoline).
- **Build model is unchanged in shape: committed + CI-gated.** Generated output is checked in at
  its real include path (`cargo regen` regenerates; `cargo regen-check` fails if the committed output
  differs). The C build sees ordinary headers — no Rust toolchain at C-build time, no build-time
  codegen.

## Considered Options

- **Keep the mirror architecture.** C is source, defs mirror, guards catch drift.
  Rejected: it is the duplication itself. Every crossing fact lives in 3–6 places and the "guard"
  only tells you *after* the fact that two hand-maintained copies diverged. ADR-0026 and ADR-0027
  are mirror-era decisions; this ADR supersedes their binding-architecture parts (the value/size
  guard reasoning of 0026, the Rust-spelling rule of 0027) — though 0027's "Rust drops the C
  prefix" survives as "defs are prefix-free and the prefix is generator policy".

- **Derive the def from the C header (reverse the dependency the other way).** Parse the
  hand-written headers, emit the def + Rust, never write the type twice. Rejected: it keeps C as
  the authoring surface (so the prefix mash, the 6× function spelling, and the
  hand-wired vtable all remain), and a C-header parser is a strictly harder, fuzzier tool than a
  small declarative IDL. It removes one copy, not the duplication.

- **Big-bang migration.** Flip every hand-written crossing type and the whole `ui/` tree at once.
  Rejected: an unreviewable, ABI-relevant change with no safe intermediate state.

- **Temporary layout-equality bridge + horizontal phasing.** An earlier draft of this ADR
  migrated all *types* first, generating each new `Fl*` type *beside* the old hand-written one and
  pinning them byte-identical with a temporary `_Static_assert`, then migrated the
  *functions* in a later phase, deleting the bridge guards at the end. Rejected: the bridge only
  exists to make a half-migrated type *coexist* with the surface that still produces the old one
  (chiefly the plugin UI vtable, whose slots were typed with the old signal type). It is pure scaffolding —
  generated, asserted, then deleted — and it buys nothing a **vertical** migration doesn't get for
  free. A domain whose functions sit *outside* the contested vtable can adopt its real `Fl*` type
  end-to-end with no coexistence at all; a domain whose functions *are* the vtable (the widgets,
  via `Signal`) only becomes migratable when the whole vtable is shipped, at which point
  there is again nothing to bridge. So the bridge is either unnecessary or premature, never load-bearing.

## Consequences

- **An ABI break is now a def edit** — caught by the same committed + `git diff` gate. A migrated
  domain needs **no drift guard at all**: api_gen generates *both* the C type (`flowi/include/flowi/<module>/<domain>.h`)
  and the Rust `#[repr(C)]` binding from the one def, so there is no second hand-maintained copy
  anywhere to drift, and nothing to assert. The old `_Static_assert` guard for that domain is
  *deleted, not repurposed*. Where a migrated type still met a hand-written type during the migration, the seam did a
  **field copy**, not a reinterpret-cast — so the two types needed not share a layout, and a reshape
  failed *that* copy to compile. No scaffolding, no silent ABI risk.
- **Hot-reload becomes possible** (both directions) because every hot caller goes through a
  generated vtable. *(Withdrawn by ADR-0032: flowi's call path is direct, and an indirection is
  only paid at a real dynamic boundary.)*
- **Plugins become a second profile, not a re-integration.** "A host loads flowi as a plugin" is a
  second profile run plus export glue, generated from the same defs.
- **Migration was incremental per-domain and *vertical*.** Each slice took one domain end-to-end —
  generate its real `Fl*` type(s), adopt them through flowi's own code, regenerate the Rust binding,
  delete the now-dead drift guard — rather than migrating all types horizontally and gluing the
  half-states with bridges. Ordering followed the vtable, not the type graph: domains whose functions
  sat outside the widget vtable went first. The migration is complete; the hand-written vtable and
  its macro families are gone.
- **The IDL grows a few constructs**: opaque/extern type declarations, handle typedef + sentinel
  `#define` emission, `const char*`/`void*` primitives, and a varargs marker (only
  `format_frame_string`). Packed enums are already modeled.
- **CONTEXT.md is unaffected by codegen vocabulary** (it stays UI-runtime domain language).
